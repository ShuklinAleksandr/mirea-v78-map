# МИРЭА В78: сборка на другом Mac и запуск на своём iPhone

Инструкция для исходного GitHub-репозитория, подготовленного 27 октября 2026 года. На другом Mac клонируйте репозиторий или распакуйте весь архив исходников и сохраните проект целиком. Одного `App.xcodeproj` недостаточно: плагины находятся в зависимостях корневого проекта.

Это исходники для новой development-сборки с подписью владельца на принимающем Mac. В архиве нет готового подписанного приложения для iPhone. Ранее выданный `MIREA-V78-iOS-Simulator.zip` предназначен только для Simulator. Публикация и TestFlight в эту инструкцию не входят.

## 1. Подготовьте другой Mac

1. Установите **полный Xcode 26 или новее**, совместимый с macOS этого Mac и версией iOS вашего телефона. На исходном Mac компиляция прошла с Xcode 26.0.1 и macOS 15.6.1. Если на телефоне более новая iOS, может потребоваться более новый Xcode; сверяйтесь с [таблицей совместимости Apple](https://developer.apple.com/xcode/system-requirements/). Только Command Line Tools недостаточно. Требование Xcode 26+ соответствует [Capacitor 8](https://capacitorjs.com/docs/getting-started/environment-setup).
2. Один раз откройте Xcode, примите лицензию и дождитесь установки запрошенных компонентов iOS.
3. Установите **Node.js 24 LTS** с [официального сайта Node.js](https://nodejs.org/en/download). В проекте `.nvmrc` содержит `24`, минимальная версия — 22.12.0. npm устанавливается вместе с Node.js. Для автоматических тестов нужен также Python 3 с доступной командой `python3`. Если используете nvm, в папке проекта выполните `nvm install` и `nvm use`.
4. Для первой подготовки нужны интернет, свободное место для Xcode и зависимостей, а для запуска — iPhone и USB-кабель с передачей данных. Android Studio, Android SDK, Java, CocoaPods и расширения Chrome **для этого iOS-прохода не нужны**: проект использует Swift Package Manager.

В Terminal проверьте команды по одной:

```sh
node --version
npm --version
python3 --version
xcode-select -p
xcodebuild -version
```

`xcode-select -p` должен указывать на `Xcode.app/Contents/Developer`. Если выбран только каталог CommandLineTools, при обычной установке Xcode исправьте выбор:

```sh
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
```

Пароль администратора вводится только в Terminal этого Mac. Если Xcode установлен в другом месте, укажите его фактический путь.

## 2. Подготовьте проект ДО открытия Xcode

Клонируйте репозиторий или распакуйте ZIP, например, в `Downloads`. Откройте Terminal, введите `cd ` с пробелом, перетащите туда из Finder папку проекта **с package.json** и нажмите Enter. Так путь с пробелами будет обработан правильно. В выбранной папке должны быть `package.json`, `src`, `public`, `android`, `ios`.

Выполняйте по одной команде, дожидаясь успешного завершения каждой:

```sh
npm ci
npm test
npm run mobile:sync
npm run mobile:check
open ios/App/App.xcodeproj
```

При ошибке остановитесь на этой команде и сохраните её полный вывод. Не продолжайте со старой копией ресурсов.

Что происходит: `npm ci` ставит зависимости для нового Mac по `package-lock.json`; тесты проверяют код; `mobile:sync` собирает веб-приложение, отбирает только В78 и синхронизирует нативные проекты; `mobile:check` проверяет комплект ресурсов. Синхронизация обновляет также Android-папку, но Android не компилирует. Не переносите `node_modules` с исходного компьютера. `npm ci` и `mobile:sync` обязательны: иначе Xcode не найдёт локальные Swift-пакеты и/или приложение откроется без карты.

В Xcode откроется **ios/App/App.xcodeproj**. Дождитесь разрешения Swift-пакетов, включая Capacitor 8.5.3, App, Keyboard, Share, **Geolocation 8.2.4 и Synapse**, а также зависимости Geolocation `ion-ios-geolocation`. Не создавайте новый проект и не запускайте `pod install`. В `Info.plist` уже добавлены обязательные описания `NSLocationWhenInUseUsageDescription` и `NSLocationAlwaysAndWhenInUseUsageDescription`; Геопозиция включается по кнопке и обновляется, пока приложение открыто; фонового слежения нет. GPS не определяет этаж автоматически; нужный план выбирается переключателем карты, а ручная точка подтверждает её план. Новый проход сборок и ограничения — [отчёт 27 октября](docs/MAP_LOCATION_UX_2026-10-27.md). Описание Always требуется библиотеке плагина и само по себе не означает запрос фонового доступа.

## 3. Выберите Apple Account и Team

Владелец входит в свою учётную запись **непосредственно в Xcode → Settings → Accounts / Apple Accounts**. Затем в левой панели Xcode выберите синий проект **App**, в разделе **TARGETS** — **App**, откройте **Signing & Capabilities**:

1. Включите **Automatically manage signing**.
2. В **Team** выберите свою команду или **Personal Team**. Если Xcode показывает **Set Up Signing**, пройдите этот шаг.
3. Исходный **Bundle Identifier** — `ru.mirea.spatialatlas`. Если он недоступен вашей Team, для личного теста задайте уникальный идентификатор, например `com.yourname.mireav78.dev`, заменив `yourname` своим уникальным значением. Это изменение целевой настройки Xcode; запишите выбранный идентификатор и используйте его для следующих установок этой личной сборки.
4. Дождитесь исчезновения ошибок provisioning/signing. Если Xcode предлагает зарегистрировать подключённый телефон, используйте **Register**.

Порядок настройки подписи описан в [инструкции Apple](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices). Пароли, коды 2FA, сертификаты и ключи никому в чат не передавайте. В исходном проекте Team намеренно не задана: принимающий Mac использует подпись владельца.

Для личного теста Apple допускает бесплатную Personal Team. Её provisioning-профили действуют **7 дней**, поэтому приложение потребуется периодически заново собрать и установить через Xcode. Ограничения Personal Team и отличие от платной программы см. в [справке Apple](https://developer.apple.com/help/account/basics/about-your-developer-account). TestFlight требует отдельной подготовки и Apple Developer Program владельца.

## 4. Подключите и подготовьте iPhone

1. Подключите разблокированный телефон кабелем и подтвердите доверие к этому Mac на самом телефоне.
2. В Xcode откройте **Window → Devices and Simulators** (в новых версиях — **Device Hub**), выберите телефон и дождитесь завершения pairing/подготовки.
3. На iPhone с iOS 16+ включите **Настройки → Конфиденциальность и безопасность → Режим разработчика / Developer Mode**, выполните запрошенную перезагрузку и подтвердите включение. Если пункта ещё нет, сначала начните сопряжение с Xcode. См. [Developer Mode у Apple](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device).
4. В верхней панели Xcode выберите схему **App**, а рядом в качестве устройства — **имя вашего физического iPhone**. Пункт Simulator или Any iOS Device не запускает приложение на вашем телефоне.

## 5. Соберите и запустите

Нажмите **▶ Run** или **Cmd+R**. Используйте конфигурацию Debug; дождитесь **Build Succeeded**, установки приложения и открытия карты на телефоне. Если iPhone запрашивает доверие к development-приложению, выполните указания iOS для своей учётной записи; телефон должен оставаться разблокированным при первой установке.

Успех этого шага — приложение установлено и запущено именно на подключённом iPhone. Development-подпись и профиль создаются на принимающем Mac. Готовый Simulator App и Debug APK для этой установки не используются. Команда проекта `npm run mobile:build:ios` тоже собирает **только Simulator** с отключённой подписью; для телефона используйте Run с выбранным устройством и Team.

Чтобы найти получившийся device `.app`: в Xcode раскройте **Products**, нажмите правой кнопкой по `App.app` → **Show in Finder**. При стандартных настройках он находится в DerivedData внутри `Build/Products/Debug-iphoneos/`. Это результат для development-тестирования; для распространения нужен отдельный подходящий архив и профиль. Не переименовывайте `.app` или Simulator ZIP в `.ipa`.

После изменений веб-кода заново выполните в корне `npm run mobile:sync` и `npm run mobile:check`, затем снова Cmd+R. Само нажатие Run не пересобирает `src/` через Vite.

## Если возникла ошибка

| Симптом                                                          | Следующий шаг                                                                                                                                                                                        |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm: command not found` или неподходящий Node                   | Установите/выберите Node 24, откройте новый Terminal, проверьте версии.                                                                                                                              |
| Xcode не находит `../../../node_modules/@capacitor/...`          | Закройте проект, выполните `npm ci` и `npm run mobile:sync` из корня, снова откройте `.xcodeproj`. Папку `ios` отдельно не переносите.                                                               |
| Swift Package Manager не скачивает Capacitor                     | Проверьте доступ в интернет к GitHub; после успешного npm/sync используйте Xcode → File → Packages → Resolve Package Versions. Сохраните точный текст ошибки, не меняйте версии зависимостей наугад. |
| `Signing requires a development team` / нет provisioning profile | Выберите TARGETS → App → Signing & Capabilities → Team и автоматическую подпись; проверьте вход владельца и наличие телефона.                                                                        |
| Bundle Identifier уже занят                                      | Укажите свой уникальный Bundle Identifier для личного теста в настройках App.                                                                                                                        |
| Телефон недоступен / Developer Mode disabled                     | Разблокируйте, проверьте доверие, кабель, pairing и Developer Mode; дождитесь подготовки устройства.                                                                                                 |
| Xcode не поддерживает iOS телефона                               | Выберите совместимую версию Xcode и macOS по таблице Apple. Понижение deployment target это не исправляет.                                                                                           |
| Приложение открылось, но карты нет                               | Проверьте успешность `mobile:sync` и `mobile:check`, затем заново установите Cmd+R. Сохраните вывод консоли Xcode.                                                                                   |

## Что проверить на настоящем телефоне

Новый проход 26 октября — `2026-10-26T18-14-39-249Z`: пройдены **385 тестов Node.js и 4 нативных Android unit-теста**, настоящие компиляции Android Debug и iOS Simulator. Последняя App запущена в iPhone 17 Pro Simulator с iOS 26.0. В Simulator проверен системный запрос доступа **Allow Once** и GPS с точностью **±5 м по подставленной тестовой координате публичного ориентира**. Это синтетический тест интерфейса и интеграции; он не измеряет точность GPS или Wi-Fi в вузе. Сведения о ресурсах бинарников и испытаниях — [отчёт нового прохода](docs/LOCATION_WIFI_2026-10-26.md); [проход по лестницам 25 октября](docs/STAIR_FINAL_2026-10-25.md) остаётся историческим.

На iPhone произвольный сбор соседних Wi-Fi-сетей скрыт; Android-сборщик сохраняет данные локально для последующего анализа и ещё не определяет положение. См. [инструкцию замеров](docs/WIFI_SURVEY.md). Подписанной device-сборки, IPA и запуска на физическом iPhone по-прежнему нет: владелец выбирает свою Team на принимающем Mac. **Перемещение карты жестом на iOS пока не подтверждено**: прежняя проверка через инструмент управления Simulator не дала видимого сдвига, причина не установлена. Два одновременных касания и офлайн-запуск последней iOS-сборки тоже не проверены. Приложение нужно испытать на телефоне.

Запишите модель iPhone, версию iOS, версию Xcode, дату и результат каждого пункта:

- Холодный запуск без сети: закройте приложение, отключите Wi-Fi и мобильные данные и снова откройте его. Карта должна загружаться из приложения.
- Перенос карты **одним пальцем**, вращение 3D **двумя**, масштабирование, переключение 2D/3D; отдельно пробуйте на пустом фоне и поверх подписи помещения. Если карта не двигается, сохраните короткую запись экрана и отметьте режим/этаж.
- Поиск `А-146`, категорий еды и туалетов; выбор результата, собственные корпус/этаж и отдельный ближайший ориентир; кнопки карточки и системная панель «Поделиться».
- Свайп нижней панели до нижней полосы и её восстановление; клавиатура, вырез экрана и нижний системный индикатор.
- Все имеющиеся уровни В78, маршрут `Г-103-1 → Г-209`, показ нескольких этажей, избранное, восстановление состояния после перезапуска, сворачивание и возврат. Отдельно отметьте задержки, сбои и расход памяти при работе с картой.

Принятая главная А2 → А3 сохранена. Нижние главные спуски, библиотечная шахта, приходы снизу и перегородки доработаны по последним ответам пользователя и имеющимся источникам; новая компиляция не подтверждает их архитектурную точность. Размеры условны; план нижнего уровня и дальнейших проходов И/ИВЦ не установлен. Неподтверждённые клетки не заполнены лестницами по аналогии. Подробности — `STAIRS_TODO_FOR_MAC.txt`; **72 пронумерованных вопроса** с ответами и статусами для обследования — `ВОПРОСЫ_ПО_КАРТЕ.md`. Unifood отложен; сведения о сети и условия сбора Wi-Fi записаны отдельно. Ответы вписывайте рядом с существующими номерами, не перенумеровывайте список.

В `public/data` и `source/maps` сохранён исходный архив четырёх площадок для воспроизводимости. Производственная мобильная сборка автоматически включает только Вернадского, 78; вручную удалять архивные карты не нужно. «Я здесь» задаёт начало вручную; автоматического indoor-позиционирования нет. Часть связности маршрутов и архитектурных данных ещё требует обследования в вузе.

В ZIP исключены SDK, `node_modules`, кэши, локальные пути окружения, сертификаты и готовые бинарники. `HANDOFF_MANIFEST.json` содержит размеры и SHA-256 исходных файлов. Старые результаты в README и документах относятся к исходному Mac; ссылки на его `.native-build` не являются журналами нового компьютера. Для этой передачи следуйте данной инструкции, а `BUILD_ON_MAC.txt` и `PROMPT_FOR_BUILD_PC.txt` используйте как исторические материалы.
