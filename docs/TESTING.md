# Проверка проекта — 20 октября 2026

Проверено на Node.js 24.8.0, npm 11.6, macOS / Apple M3 Max. Проверки интерфейса выполнялись во встроенном Chromium на production-сборке через `npm run preview`.

## Повторяемые проверки

```sh
npm ci
npm run check
npm audit
node scripts/check-routing.mjs
npm run mobile:build:ios
npm run mobile:build:android
npm run mobile:check
```

`check` проверяет форматирование, запускает тесты на реальных JSON/геометрии Three.js и собирает приложение. Финальный проход после поправки наружных переходов, контраста маршрута и редактирования конечных точек: **108 тестов пройдены, 0 ошибок и пропусков**, production-сборка успешна. `npm audit` — 0 известных уязвимостей.

Основное покрытие:

- Все 23 плана, 58 изображений, ссылки на ресурсы, конечные координаты стен и дверей.
- Физическая нумерация этажей, разрешение поисковых результатов, все 86 исходных лестничных переходов.
- Асинхронные гонки при выборе площадки, этажа и конечных точек; отменённый расчёт не возвращает устаревший маршрут.
- Маршруты через настоящие двери; запрет выдуманных прямых связей и сокращений через посторонние аудитории; направленные рёбра и корректные повороты.
- Камеры и OrbitControls, вертикальность 2D, масштабирование, возвращение в 3D, размещение маршрута над мобильной панелью.
- Несколько этажей на исходных относительных высотах, сохранение выбранного этажа, лестничные марши и площадки, освобождение геометрии при смене режима.
- Обе ветви главной лестницы А, различие форм А2/А3, спуск верхней формы через прорезь перекрытия и отдельная лестница А3→А4.
- Наружные объёмы, кровли, просветы переходов, сохранение контуров помещений.
- Мобильная панель, повреждённые сохранённые настройки, native lifecycle, Android Back, безопасное восстановление внутренних ссылок.
- Редактирование готового маршрута сохраняет обе выбранные точки; новый расчёт получает обновлённое назначение.
- Восемь интеграционных сценариев запуска/остановки сервера: повторный и одновременный запуск, сигналы завершения, занятый чужим процессом порт и восстановление после аварийного завершения.

## Геометрия и маршрутизация

Геометрический аудит: 4453 полигона, 40742 участка стен и 2600 дверных проёмов; невалидных полигонов и перекрытых дверных разрывов не найдено. Для 59 лестничных форм остаются два явно описанных расхождения исходных материалов Г1/В1; новых необъяснённых существенных выходов за границы нет. См. [STAIRS.md](STAIRS.md) и `analysis/stair-coverage-qa.json`.

Алгоритм маршрутизации сравнен с независимым Floyd–Warshall на 3300 направленных парах. Аудит реальных данных охватывает 4800 направленных попыток на всех 17 исходных уровнях трёх площадок: 1934 корректных пути и 2866 отказов. Из отказов 2198 связаны с разными компонентами исходного графа, 668 — с запретом прохода через посторонние подписанные помещения. Для Малой Пироговской граф отсутствует. Это характеристика выборки, а не обещание маршрута между любой парой аудиторий. Результат — `analysis/routing-runtime-qa.json`, описание — [ROUTING.md](ROUTING.md).

Планы, лестницы и граф связаны контрольными суммами: изменение исходной геометрии без пересборки маршрутов обнаруживается тестами. Изолированная пересборка данных из `scripts/` и `source/maps/` ранее воспроизвела 55 файлов побайтно (`analysis/portable-build-qa.json`).

## Проверка интерфейса

Пройдены 46 сочетаний уровня и проекции: каждый из 23 уровней в 2D и 3D. Дополнительно проверены 8 внешних видов: четыре площадки в двух проекциях. В каждом случае проверены завершение загрузки, наличие canvas, выбранный этаж и отсутствие экрана ошибки. Этот проход проверяет загрузку; сам по себе он не доказывает визуальную правильность каждого полигона. Результат — `analysis/browser-qa-2026-10-20.json`.

Вручную проверены поиск Г-214 с другой площадки, карточка помещения, избранное, выбор начала/конца, пошаговое прохождение, переключение 3D/2D, дневная и ночная темы, фокус этажа в многоэтажном маршруте и возвращение к кампусу. Отдельно проверены одинаковые конечные точки, разные площадки и отсутствие графа МП-1. Карта объясняет невозможность расчёта и не показывает выдуманный путь.

После удаления элементов разработчика проверено отсутствие кнопки пожарных планов в верхней панели и ссылок на исходники в карточках. Пользователю доступны карта, поиск, маршруты, этажи и настройки. Снимки финальных проверок сохраняются в `analysis/ui-2026-10-20/`.

В окончательной сборке повторно осмотрены внешний кампус, маршрут Г-103-1→Г-209 на двух этажах и А-7→А-305 через главную лестницу. Визуальная проверка выявила, что прозрачная архитектура перекрывала маршрут из-за порядка очередей отрисовки; исправлено и закреплено регрессионным тестом. Проверены фокус второго этажа без выхода из многоэтажного режима, переход к одиночному 2D-плану, тёмная тема и изменение назначения Г-209→Г-112 с сохранением начала.

## Мобильные приложения

Общий интерфейс и все данные включены в проекты iOS/Android через Capacitor. Сборки проверяются отдельно от web-сборки. `mobile:check` сравнивает SHA-256 полного набора публичных данных между источником, `dist`, iOS и Android, проверяет отсутствие удалённого `server.url` и полноту офлайн-пакета. Результаты финальных нативных сборок и расположение артефактов — [MOBILE.md](MOBILE.md).

## Границы проверки

Автоматические проверки и визуальный осмотр не заменяют обмеров здания. Шаг этажей 3.6 м — параметр модели, а не подтверждённая высота. Часть наружных деталей и привязок лестниц приблизительна. Различаются индекс исходного плана, локальный номер этажа корпуса и наружная высота. Последние уточнения переходов пользователем отражены в [аудите источников](SOURCE_REVIEW_2026-10-20.md).

Физические телефоны, полный пользовательский проход в финальных нативных сборках, слабые GPU и все версии Safari/Android WebView не проверены. Успешная компиляция iOS для симулятора не означает готовность подписанного приложения для установки на iPhone или публикации в App Store. Внутреннее позиционирование не реализовано: начало маршрута и переход к следующему шагу пользователь задаёт вручную.
