Карта использует один JavaScript-код, Three.js-сцену и граф маршрутов в браузере и двух нативных приложениях на Capacitor 8.5.3. Проекты находятся в `ios/` и `android/`. Приложения открывают **локальный комплект файлов**, без сайта на внешнем сервере и регистрации. Разрешение на местоположение требуется только при явном включении геопозиции или Android-замере Wi-Fi; ручной выбор, карта, поиск и маршруты обходятся без него. Приложение не определяет физический этаж автоматически. На Android сборщик радиокарты использует собственный native-плагин; на iOS эта кнопка скрыта.

### Один Mac для Android и iOS

На одном Mac можно собирать обе платформы. Для этого проекта подготовлена команда `npm run mobile:build:macos`. Она получает Android Debug APK и приложение для **iOS Simulator**. Установка на физический iPhone и TestFlight требуют отдельной сборки с подписью; Simulator App для этого не подходит.

Перед первым запуском подготовьте:

1. Mac с macOS, совместимой с выбранным **полным Xcode 26 или новее**. Для Xcode 26.0 минимальна macOS Sequoia 15.6; у новых Xcode требования могут быть выше. Совместимость конкретной версии проверяется по [таблице Apple](https://developer.apple.com/xcode/system-requirements). Одних Command Line Tools недостаточно: откройте Xcode, примите лицензию и установите предложенные компоненты. В Settings → Locations выберите его Command Line Tools.
2. Node.js 22.12+ с npm. После переноса проекта установите зависимости заново командой `npm ci` на Mac. Переносить Windows `node_modules` не нужно.
3. Android Studio 2025.2.1+ либо настроенный SDK с JDK 21+. В SDK Manager нужны Android API 36, **Build Tools 35.0.0**, platform-tools и принятые лицензии. Версия Build Tools взята из default текущего AGP 8.13, а не из номера API: [таблица совместимости Android](https://developer.android.com/build/releases/agp-8-13-0-release-notes). Используйте SDK для этого Mac; путь задаётся `ANDROID_HOME`, JDK — `JAVA_HOME`.
4. Интернет для первой установки npm/Gradle/Maven/Swift Package Manager. После копирования архива при необходимости дайте wrapper право запуска: `chmod +x android/gradlew`.
5. Для запуска iOS установите iOS Simulator runtime в Xcode Settings → Components. Для generic Simulator-компиляции достаточно SDK; отсутствие runtime показывает рекомендацию и не блокирует сборку. Для проверки настоящих жестов, памяти и офлайн-режима понадобятся Android-телефон и iPhone.

Из корня проекта на подготовленном Mac:

```sh
npm ci
npm run mobile:build:macos
```

Команда сначала проверяет окружение, затем выполняет тесты, **один** `mobile:sync` для обеих платформ, контроль нативных комплектов, Android launcher и `xcodebuild` для Simulator. Веб-комплект повторно не пересобирается между платформами. При ошибке следующие этапы не запускаются. Только успешные команды и наличие обоих ожидаемых результатов позволяют вывести итоговый успешный статус.

Результаты:

| Файл                                                             | Назначение                                                                                                                      |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `android/app/build/outputs/apk/debug/app-debug.apk`              | Установка для испытаний на Android; Gradle применяет стандартную отладочную подпись. Это не release для магазина.               |
| `.native-build/ios/Build/Products/Debug-iphonesimulator/App.app` | Только iOS Simulator на Mac, без подписи. Не устанавливается на iPhone и не загружается в TestFlight.                           |
| `.native-build/macos/<время-запуска>/status.json` и `*.log`      | Статус и журнал каждого этапа. Если, например, Android собрался, а iOS завершился ошибкой, общий результат остаётся неуспешным. |

Для физического iPhone откройте `ios/App/App.xcodeproj` в Xcode, выберите свой телефон и Team в Signing & Capabilities. Для личных испытаний Apple допускает Personal Team с ограничениями; условия описаны в [правилах аккаунта разработчика](https://developer.apple.com/help/account/basics/about-your-developer-account). Для TestFlight нужны участие владельца в Apple Developer Program, приложение в App Store Connect и подписанный архив для устройства. Настройка Team, сертификатов, профилей и загрузка выполняются отдельно с аккаунтом владельца: [TestFlight](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview). Общая команда ничего не публикует и не использует release-ключи владельца.

## Офлайн-пакет и обновление

`mobile:sync` выполняет production-сборку, создаёт `dist/mobile-package.json` и копирует пакет в оба приложения. В поставку входят только Вернадского, 78: пять уровней исходного плана, граф маршрутов, каталог, окружение и фотографии для сверки. Фильтр применяется при каждой производственной сборке, в том числе после повторной генерации полного исходного архива. Новые слои должны быть явно включены в `scripts/lib/release-data.mjs`. Его размер, версия и контрольные суммы файлов записаны в дескрипторе. Данные читаются по необходимости; наличие в пакете не означает одновременную загрузку всей геометрии в GPU.

`npm run mobile:check` проверяет SHA-256 всех собранных файлов в обеих нативных копиях и совпадение с проекцией исходников В78. Проверка также обнаруживает оставшиеся файлы исключённых площадок. После изменения данных или интерфейса выполните `mobile:sync` заново.

Комплект обновляется атомарно вместе с приложением. Геометрия и граф берутся из одной сборки, поэтому скачивание несовместимых версий по отдельности невозможно. Удаление/скачивание отдельных площадок и фоновый сервер обновлений пока не реализованы. Карта, поиск и маршруты используют локальный пакет. Ссылки и кнопки просмотра исходных пожарных планов из пользовательского интерфейса удалены. В браузере `npm run build` сам по себе не создаёт офлайн PWA.

## Нативные взаимодействия

`src/mobile.js` подключается до запуска карты:

- стартовая ссылка или сохранённый URL восстанавливают вид карты;
- при сворачивании сохраняется URL, при возврате отправляется resize;
- `atlas:app-state` передаёт состояние активности сцене;
- сцена останавливает единственный цикл кадров в фоне, учитывая также видимость страницы; повторные события возврата не запускают второй цикл;
- Android «Назад» закрывает диалог, клавиатуру или карточку; интерфейс может закрыть свою панель через `preventDefault()` события `atlas:back`; на главном экране приложение сворачивается;
- цвет системных значков следует теме;
- safe areas используют CSS `--safe-area-inset-*` с fallback на `env(safe-area-inset-*)`;
- `adjustResize` оставляет место клавиатуре на Android.

[Документация App API](https://capacitorjs.com/docs/apis/app) и [System Bars](https://capacitorjs.com/docs/apis/system-bars).

Схема ссылок зарегистрирована на обеих платформах:

```text
mireamap://map#campus=v-78&view=floor&floor=v-78-floor2&projection=2d
```

Идентификаторы помещения/этажа берутся из данных. Допустимы ключи `campus`, `building`, `floor`, `view`, `projection`, `room`, `from`, `to`; фактическое существование объектов проверяет загрузчик карты. Ссылка не может подменить URL сервера или открыть произвольную страницу внутри приложения. Universal Links/App Links с доменом требуют домена владельца и здесь не настроены.

## Проверка

`tests/mobile.test.mjs` проверяет сохранение русских номеров и параметров маршрута, отбрасывание чужих схем, хостов, неизвестных параметров и чрезмерно длинных значений. `tests/mobile-lifecycle.test.mjs` проверяет приоритет стартовой ссылки над сохранённым видом, сохранение/возврат из фона, системную тему и порядок Android «Назад». `tests/ui-controller.test.mjs` проверяет жест панели, повреждённые сохранённые настройки и гонки вычисления маршрута. Эти тесты исполняют production-контроллеры с заглушками DOM, WebGL и нативного API, поэтому не заменяют проверку отрисовки на устройстве.

Версии зависимостей фиксируются в `package-lock.json`. Для зависимости сборочного парсера `xcode` установлен совместимый `uuid` 11.1.1: используется его API `v4`, проверяемый при `cap sync`.

Архив `.native-tools/android` был подготовлен на Mac. Он не является готовым Windows SDK; текущую пригодность проверяет `mobile:doctor`. Нельзя считать папку с платформой достаточным подтверждением готовности сборки.

На реальных телефонах перед выпуском нужны проверки жестов, клавиатуры, safe areas, расхода памяти/GPU, фонового режима и холодного офлайн-запуска. Успешная компиляция не заменяет эти проверки и не подтверждает 60 FPS на устройствах.
