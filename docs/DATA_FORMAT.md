# Формат данных карты

Текущая схема имеет `schemaVersion: 1`. JSON лежат в `public/data/`; приложение обращается к ним как к `/data/...`. Это данные для отображения сохранённых материалов, а не BIM или геодезическая модель.

## Координаты и этажи

Планарная точка `[x, z]` соответствует горизонтальным осям Three.js; вертикальная ось — `y`. Числа `bounds` идут как `[minX, minZ, maxX, maxZ]`. Не назначайте географический север по направлению плана.

Для В-78, В-86 и С-20 `units: "meters"` следует метаданным источника. `sourceScale` сохраняет пересчёт, исходный центр и направление оси. Это не свидетельство полевого измерения. Для МП-1 `units: "map-units"`: метры и площади по этой геометрии не определяются.

`floor.level` — уровень источника. `buildingLevels` связывает литеру корпуса с физическим этажом. Например, `v-78-floor1` содержит А1 и Г2. `sourceInternalLevel` — ещё один внутренний индекс источника; его нельзя использовать вместо физического этажа. У МП-1 файл `mp-1-floor0.json` содержит цоколь с `level: -1`.

## Основные файлы

| Файл                             | Данные                                                                                                                                                   |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `manifest.json`                  | Площадки, адреса, корпуса, уровни, ссылки на JSON/SVG, соответствие этажей, масштаб и общие ограничения.                                                 |
| `campuses/<campus>/<floor>.json` | Полная геометрия и происхождение одного уровня.                                                                                                          |
| `search-index.json`              | 2659 каталожных записей: `id`, `label`, `kind`, `building`, `campusId`, `floorId`, `level`, `center`, `confidence`, `hasPolygon`, `sourceUrl`.           |
| `photo-index.json`               | 58 изображений; `id`, `file`, `originalFile`, `caption`, `building`, `floor`, заметки и прочитанные подписи. `floor` здесь — физический этаж фотографии. |
| `plans/<campus>/<floor>.svg`     | Векторные исходники для сравнения с моделью.                                                                                                             |

Поле `roomCount` в исходном формате сохранено, но включает разные каталожные объекты, не только комнаты. Поиск может вернуть исходную точку без полигона (`hasPolygon: false`); её нельзя превращать в придуманное помещение.

## Файл уровня

- `polygons` — области. `points` содержит внешнее кольцо без повторённой последней точки, `holes` — внутренние кольца. `id` стабильно связывает объект с другими файлами. `roomId` бывает `null` у неподписанной области. `label` и `kind` сохраняют доступную подпись и тип.
- `walls` — линейные участки `{a, b, source, confidence}`. Их толщина и высота задаются отдельно, а не извлекаются из этих линий.
- `doors` — исходные дверные разрывы `{id, a, b, source, confidence}`; они не задают створку, высоту или направление открывания.
- `footprints` — объединённые области уровня. `exteriorFootprints` исключают явно распознанные наружные подходы. `outdoorPolygons` не экструзируются как корпуса.
- `markers` и `transitions` — исходные точки и навигационные связи. Переход имеет `position`, `targetFloorId` и `targetPosition`; это связь графа, а не обмер марша.
- `source` — архив, исходный файл/слой, URL, контрольная сумма, статус переноса и `physicallySurveyed`. `sourceScale` — параметры координатного пересчёта.
- `uncertaintyRegions` и `placementConfidence` — отдельные ограничения размещения. `confidence: "source-plan"` у комнаты не отменяет `placementConfidence: "unverified"` у её блока.

`kind: "unclassified"` означает неизвестное назначение. `sourceKind` сохраняет тип до обоснованной переклассификации; `classification` описывает причину и доказательства. `exteriorEligible: false` запрещает использовать уличную область для построения наружного объёма.

## Внешняя модель и допущения

| Файл                                                                            | Значение                                                                                                                                                                  |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `assumptions.json`                                                              | Принятая высота уровня, высота и толщина стен, общие ограничения.                                                                                                         |
| `stair-assumptions.json`                                                        | Приблизительные вертикальные размеры, поручни, целевой шаг визуальных ступеней и маркер неизвестной формы.                                                                |
| `stair-layouts.json`                                                            | Фотопривязанные формы: исходные полигоны и фотографии, рамка в плане, отдельные марши и площадки.                                                                         |
| `exterior-special.json`                                                         | Приблизительный округлый объём конференц-зала и явно нерешённая привязка поднятого спортивного перехода.                                                                  |
| `exterior-shells.json`                                                          | `campuses[id].shells`: производные объёмы с `base`, `height`, `points`, `holes`, `sourceFloorId`, `heightStatus`. `facadeBands` задаёт видимые фасадные интервалы высоты. |
| `exterior-shells.json` → `displayShells`, `displayFacadeBands`, `displayPolicy` | Отдельная коррекция наружного показа: объединение равновысоких участков и подъём узких фрагментов к соседней кровле. Исходные комнаты и `shells` сохраняются.             |
| `exterior-overrides.json`                                                       | Разрешённые по материалам низкие объёмы, диапазон предполагаемой высоты и основания. Генерируется из `scripts/exterior-overrides.json`.                                   |
| `exterior-hall.json`                                                            | Контур низкого входного павильона, отдельные объём/крыша, сегменты остекления, глухой фасад А, оценочный козырёк.                                                         |
| `facade-style.json`                                                             | Условный ритм окон и кровельные детали по фотографиям; источники и ограничения.                                                                                           |
| `exterior-context.json`                                                         | Сохранённое окружение OSM, атрибуция и приблизительное совмещение. Это отдельный слой, не новые помещения университета.                                                   |

`lowerInteriorStatus: "not-inferred"` означает, что опущенная до условной земли оболочка не создаёт неизвестных нижних помещений. Для внутренних планов всегда используются `polygons`, а не наружные `shells`.

У входного павильона `volumePolygons` вычитают пересечение с высоким А, `roofPolygons` сохраняют сплошную крышу, а `replaceShellOverrideIds` перечисляют исключаемые дубли из общего экстерьера. `frontGlazingSegments` и `visibleTopWallSegments` задают участки без общих декоративных окон. `topWallSegments` сохраняют исходную границу с вестибюлем; видимые сегменты получены по наружным высотным полосам, поскольку верхние планы А не полностью совпадают с ней. `topWall.noRegularWindowRows` отражает преимущественно глухой фасад на фото; рисунок мозаики отсутствует.

## Лестницы

`stair-layouts.json.layouts[]` содержит `id`, `campusId`, `floorId`, `building`, `physicalFloor`, `sourcePolygonIds` и `sourcePhotoIds`. `fitAreaId` связывает небольшой исходный участок с моделью; у лестниц внутри большого холла он может быть отдельным идентификатором модели, а не ID всего холла.

`frame` задаёт `origin`, единичные `axisU`/`axisV` и `size` в координатах карты. Точки `flights[].from/to` и `landings[].points` нормированы в этой рамке. Марши содержат ширину и условные `baseFraction`/`topFraction`; площадки — `elevationFraction`. `treadCount: null` означает, что реальное число ступеней не прочитано. Количество ступеней отображения вычисляется отдельно и не переписывает источник. `shapeStatus`, `placementStatus` и `verticalStatus` различают наблюдаемую форму, размещение и приблизительную высоту.

Навигационные переходы по-прежнему берутся из графа исходной карты. Форма, найденная на фотографии, не создаёт неизвестную связь между этажами. Точка графа без подтверждённой формы остаётся символом ↕. Детали и порядок уточнений: [STAIRS.md](STAIRS.md).

## Окружение

`exterior-context.json` содержит кэш OSM с атрибуцией и параметрами приблизительного аффинного совмещения. Соседние здания — контекст, а не новые корпуса университета. Интерфейс включает слой по умолчанию; сохранённое поле экспорта `defaultVisible` не управляет начальным состоянием приложения. Улицы и границы не считаются геодезически совмещёнными с внутренними планами.

## Достоверность новых данных

Новая запись должна сохранять идентификатор источника, происхождение координат и отдельные статусы по горизонтальной геометрии, высоте и размещению. Фотография подтверждает видимый признак, но не делает оценённый размер точным. Не заменяйте отсутствующее значение нулём или догадкой. Не объединяйте LiDAR с планом, пока единое преобразование не подтверждено несколькими независимыми ориентирами; текущая гипотеза находится только в `analysis/lidar-registration.json` и не применяется к сцене.
