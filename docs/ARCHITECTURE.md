# Архитектура и продолжение разработки

Приложение состоит из трёх независимых частей: исходные материалы, подготовленные данные и их отображение. Three.js не распознаёт планы при запуске. В браузер поступают уже проверяемые JSON и SVG из `public/data/`.

## Навигация по репозиторию

| Путь                               | Ответственность                                                                          |
| ---------------------------------- | ---------------------------------------------------------------------------------------- |
| `src/main.js`                      | Точка входа приложения и подключение стилей.                                             |
| `src/app.js`                       | Сценарии: площадка → корпус → уровень → помещение; связывание интерфейса со сценой.      |
| `src/map/scene.js`                 | Three.js renderer, камера, управление, выбор объектов, слои и жизненный цикл геометрии.  |
| `src/map/exterior.js`              | Наружные оболочки, фасадные элементы и отдельный слой окружения.                         |
| `src/map/hall.js`                  | Широкий низкий входной павильон Вернадского, 78 и глухой фасад А позади него.            |
| `src/map/stairs.js`                | Марши и площадки по конкретным фото; неизвестные конструкции остаются точечными знаками. |
| `src/data/utils.js`                | Нормализация объектов, соответствие уровня этажу корпуса, признаки достоверности.        |
| `src/data/navigation.js`           | Состояние площадки, корпуса и уровня в URL.                                              |
| `src/data/spatial.js`              | Пространственное сопоставление исходных точек и областей.                                |
| `src/data/client.js`               | Загрузка подготовленных данных.                                                          |
| `src/ui/layout.js`                 | Разметка интерфейса.                                                                     |
| `src/ui/sources.js`                | Просмотр исходных планов, фотографий и сведений о достоверности.                         |
| `src/ui/search.js`                 | Поиск по каталогу.                                                                       |
| `src/ui/icons.js`, `src/ui/dom.js` | Общие значки и небольшие функции интерфейса.                                             |
| `src/styles.css`                   | Оформление интерфейса.                                                                   |
| `source/maps/`                     | Извлечённые цифровые оригиналы, исходный каталог и сохранённый OSM XML.                  |
| `source/lidar/`                    | Исследованный скан; рабочая сцена его не загружает.                                      |
| `scripts/`                         | Конвертеры, явно заданные классификации и параметры наружных объёмов.                    |
| `public/data/`                     | Готовые данные приложения; часть файлов генерируется скриптами.                          |
| `analysis/`                        | Аудиты, контрольные суммы, изображения для сверки и нерешённые гипотезы.                 |
| `tests/`                           | Проверки важных связей между данными, переключения этажей и исключений наружной модели.  |

Подробные поля описаны в [DATA_FORMAT.md](DATA_FORMAT.md). Не переносите предположение о высоте, назначении или принадлежности здания в поля исходной геометрии: храните его отдельным слоем с причиной и ссылкой на материал.

## Как обновить помещение или этаж

1. Найдите `id` объекта в `public/data/search-index.json`, затем его `floorId` и полигон в `campuses/<campus>/<floor>.json`. Посмотрите `source`, исходный SVG и фотографию.
2. Проверьте физический этаж через `buildingLevels`. В В-78 один уровень содержит разные физические этажи нескольких корпусов. Не вычисляйте этаж из строки номера помещения.
3. Для исправления исходного переноса измените конвертер `scripts/build-data.py`. Для подтверждённой переклассификации используйте `scripts/map-classifications.json`: сохраните исходный тип, укажите причину и источники. Проверка SHA защищает от применения правки к другой версии SVG.
4. Пересоберите данные и производные наружные слои. Не ограничивайтесь ручным редактированием сгенерированного JSON: следующая сборка его перезапишет.
5. Выполните проверки, откройте помещение через поиск и осмотрите соседние комнаты, дверные разрывы, номера этажей и исходный план.

Неподписанный полигон остаётся `unclassified`, пока назначение не подтверждено. Точечный маркер лестницы не создаёт доказанного лестничного помещения. Коррекция ошибки исходной карты должна сохранять исходное значение и основание решения.

## Как уточнить внешний вид

Наружная оболочка выводится из планов, но хранится отдельно от интерьера. `scripts/exterior-overrides.json` задаёт особые низкие объёмы; `scripts/build-exterior-shells.py` собирает `exterior-shells.json` и разрешённые переопределения. Поля `displayShells` и `displayPolicy` отделяют сглаживание мелких ступеней крыши от исходных `shells`.

Входной павильон формирует `scripts/build-exterior-hall.py`. `volumePolygons` исключают пересечение с сохраняемым высоким А, а `roofPolygons` задают единую крышу. Его `replaceShellOverrideIds` исключаются из общей оболочки перед добавлением `createEntranceHall()`. Декоративные окна не должны попадать на `frontGlazingSegments` или `visibleTopWallSegments`: там работает отдельный модуль. На высоком фасаде не рисуется выдуманная мозаика.

`build-exterior-special.py` хранит отдельный округлый наружный объём конференц-зала; его форма аппроксимирует видимый периметр и фото, а не повторяет выемки внутренних комнат. Отдельно записано отсутствие надёжной привязки поднятого перехода у спортзала: его положение не достраивается догадкой.

Сначала уточняйте контур и высоту крупного объёма, затем кровлю и детали. Не делайте гладкую наружную крышу веером по сложному контуру внутренних комнат; внешний контур и карниз требуют отдельного основания. Просвет под поднятым переходом допустим только там, где его положение подтверждено. Отсутствие нижнего плана само по себе не доказывает открытый проход.

Геометрию одного материала объединяйте в несколько крупных мешей. Не оставляйте совпадающие поверхности крыши или декор точно в плоскости фасада: это вызывает мерцание. Равномерные окна, поручни и стойки остаются приближением даже при точном переносе горизонтального контура.

## Пересборка данных

Обычный `npm run build` собирает приложение из готовых JSON. Полная конвертация требует Python 3 и библиотек из `scripts/requirements-data.txt`. По умолчанию используется сохранённый набор `source/maps/original/pulse/` и каталог; родительские архивы и сеть не нужны.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r scripts/requirements-data.txt
python scripts/build-all.py
npm test
npm run build
```

`build-all.py` запускает все этапы одним интерпретатором и останавливается на первой ошибке: `build-data` → `build-stair-layouts` → `build-exterior-special` → `build-exterior-shells` → `build-exterior-hall` → `build-exterior-context` → `build-photo-details` → `check-data` → `check-stair-layouts`. Фасадные полосы должны существовать до генерации видимых участков высокого фасада входа. `npm run data:build` вызывает тот же сценарий через `python3`; активируйте нужное окружение заранее. `npm run data:check` проверяет готовую геометрию.

Для нового извлечения с аудитом оригиналов выполните `python scripts/build-all.py --from-archives`. Этот режим требует одновременно `mirea-maps.zip`, `Ninja+Mirea_5.3.0_APKPure.xapk` и `index.html` в родительской папке. Другую папку задаёт `--archives-dir /путь/к/оригиналам`. При отсутствии любого файла процесс завершается до извлечения. `--help` есть у общего сценария и конвертера.

Обычная пересборка считает SHA-256 реально прочитанных кэшированных файлов. Результат прежнего архивного аудита хранится отдельно в `source/maps/archive-audit.json`; он не объявляется новым выполненным сравнением архивов. `matchesCurrentCachedAssets` показывает, совпадает ли текущий кэш с проверенным набором.

Конвертация HEIC и OCR были исследовательским шагом на macOS. Все 58 браузерных изображений и реестр уже подготовлены; общая пересборка их не распознаёт заново. Формы лестниц описаны явной конфигурацией и привязкой к фотографиям; см. [STAIRS.md](STAIRS.md).

## Проверка перед передачей

`npm test` проверяет данные и связи, но не изображение WebGL. `tests/assets.test.mjs` также проверяет весь граф публичных ссылок, наличие 23 SVG, целостность и размеры 58 JPEG, ссылки на фотографии и отсутствие LiDAR-моделей в `public/`. После успешной сборки откройте приложение и проверьте общий вид, входной павильон, открытые дворы, переход «Кампус/Этаж», разные корпуса и физические этажи. Найдите номер на текущей и другой площадке, откройте карточку и доступный лестничный переход; проверьте возврат к обзору и 2D/3D.

Осмотрите фасады при вращении и вблизи: мерцание, пропавшие поверхности, слишком частые оконные линии и ступени кровли не выявляются проверкой JSON. При замедлении отдельно сравните слои фасадов и окружения. Изменение источника, которое меняет покрытие или достоверность, сопровождайте обновлением [SOURCES.md](SOURCES.md).

## Жизненный цикл локального сервера

`npm run dev`, `npm run preview` и `npm run stop` вызывают `scripts/serve.mjs`. Скрипт запускает Vite в своём процессе и хранит отдельный управляющий IPC-сокет для каждого режима. Путь сокета зависит от канонического пути проекта; на macOS/Linux он расположен в приватном временном каталоге, на Windows используется named pipe. Второй запуск сначала просит предыдущий сервер закрыть Vite и освободить порт. Список чужих PID не обходится и процессы по номеру порта не завершаются.

При SIGINT/SIGTERM/SIGHUP и исчезновении родительского npm сервер закрывается. Оставшийся после аварии сокет проверяется и удаляется следующим запуском. Если предпочтительный порт занят другой программой, Vite выбирает свободный; фактический URL печатается в терминал. Удалять `node_modules` или переустанавливать зависимости следует после `npm run stop`. Проверки находятся в `tests/launcher.test.mjs`.


## Интерфейс, маршруты и мобильные приложения (20 октября 2026)

`src/ui/routes.js` управляет двумя точками, поиском, асинхронным расчётом, обзором этажей и ручными шагами. `src/data/route-worker.js` выносит загрузку и поиск пути из потока интерфейса; версия запроса не даёт устаревшему результату перезаписать новый выбор. `src/data/routing.js` содержит чистый расчёт пути, исходные графы воспроизводимо экспортирует `scripts/build-routing.py`.

`src/map/route.js` отвечает за линию, стрелки и маркеры, а сцена связывает их с этажами и фотографически описанными лестницами. Исходная геометрия не заменяется декоративной линией маршрута. Отображение нескольких этажей использует принятые высотные отметки модели, без искусственного увеличения межэтажного расстояния.

`src/ui/experience.js` хранит настройки, историю и избранное локально, управляет нижней панелью. `src/styles.css` полностью заменён новым оформлением; внешняя загрузка Google Fonts удалена. `src/mobile.js` подключает платформенный жизненный цикл и разрешённые deep links. Сборки `ios/` и `android/` включают локальные данные и Web Worker. `mobile:check` сверяет хеши исходных, веб- и нативных ресурсов, обнаруживая устаревший пакет.
