# Единый интерфейс карты

В ветке `main` используется единый интерфейс карты. История сравнения вариантов описана в [отдельном отчёте](INTERFACE_COMPARISON_BUILD_2026-11-08.md).

Один проект используется для Android, сайта на компьютере и мобильного веба, включая Safari на iPhone. Данные карты и граф маршрутов общие.

Тестовый выпуск **[v0.5.5](https://github.com/ShuklinAleksandr/mirea-v78-map/releases/tag/v0.5.5)**, Android `versionCode=9`. ## Управление картой

- На телефоне верхний ряд содержит компактные действия «Все корпуса», «Снаружи», «Внутри» и 2D/3D. Иконки сохраняют доступные текстовые названия и области нажатия не менее 44 px.
- В обеих ориентациях телефона кнопка со слоями и номером открывает цифры этажей. Заголовок диалога уточняет корпус; там же доступны его аудитории. На экране отображается один выбранный план.
- В горизонтальном положении поиск, карточка места и маршрут находятся сбоку. Карта остаётся видимой; панель сворачивается в кнопку.
- При вводе активное поле, прокручиваемые подсказки и «Готово» занимают видимую область над клавиатурой. Если высоты мало, поле и результаты располагаются рядом. После выбора первой точки маршрута открывается второе поле с подсказками.
- Через 6 секунд без действий на карте её кнопки скрываются. Первое короткое нажатие возвращает кнопки, следующее позволяет выбрать место. Пока маршрут построен, карточка маршрута остаётся доступной.
- Один палец перемещает карту. Щипок меняет масштаб, разворот двух пальцев вокруг друг друга поворачивает карту в 2D и 3D. Движение двух пальцев вместе перемещает карту. Все три действия можно сочетать без отрыва пальцев; точка под их центром остаётся на месте относительно жеста. Наклон 3D не меняется случайно при приближении. Переход 2D/3D сохраняет направление.
- Карточка маршрута показывает текущий шаг, направление и доступные действия. При надёжной геопозиции шаги меняются автоматически; при недостаточных данных остаются ручное управление и уточнение точки.
- Качество по умолчанию — «Баланс». «Автоматически» может снижать детали при устойчиво тяжёлой отрисовке; ручное качество и лимит кадров остаются отдельными настройками.

## Номер этажа и геопозиция

Один исходный план может включать разные физические этажи соседних корпусов. Номер на кнопке уточняется по корпусу в текущем плане, а не по высоте GPS.

Контекст может определяться по центру просмотра внутри однозначной области корпуса, подтверждённой точке пользователя или текущему существующему участку маршрута. Для GPS требуются свежие координаты и допустимая погрешность: точка вместе с областью неопределённости должна помещаться внутри однозначной зоны. Ближайшая аудитория или прямоугольные границы корпуса не служат заменой этому условию. На стыке корпусов и при неоднозначности сохраняется последний понятный контекст.

Такое уточнение меняет подпись и список этажей корпуса, сохраняя выбранный исходный план, камеру и маршрут. **GPS не определяет этаж.** Для перехода на другой этаж выберите его или подтвердите лестничный переход в маршруте.

Поиск ближайших мест сравнивает доступные пути по существующему графу либо явно указывает расстояние «по прямой». Расстояния и геопривязка приблизительны; прямое расстояние не подтверждает проход через стены. Ввод «еда» объединяет известные места питания, без выдуманной точки Unifood.

## Сохранённые данные и старые ссылки

Ссылки с `?interface=classic` и `?interface=next` по-прежнему открываются, но ведут в одно приложение. Для новых ссылок этот параметр не нужен. Часть адреса после `#` сохраняет место, этаж и параметры маршрута.

При обновлении выполняется однократный перенос локальных данных:

- Настройки и данные прежнего нового интерфейса сохраняются в его существующем хранилище.
- Избранное и недавно открытые места из обоих прежних профилей объединяются без дубликатов.
- Если соответствующего значения в основном профиле нет, из старого профиля копируются настройки, сохранённый нативный вид и локальные записи GPS-уточнений. Уже имеющиеся настройки и записи не перезаписываются.
- Исходные записи не удаляются. После успешного переноса удалённое пользователем избранное не возвращается при следующем запуске. Если браузер запретил запись, карта продолжает открываться, а перенос повторяется при следующей возможности.

Перенос действует в пределах того же браузера или установленного приложения. Это не синхронизация между устройствами. На сервер личные записи автоматически не отправляются.

## Запуск на Mac, Windows и Linux

Нужны Node.js 24 и Git. В Terminal или PowerShell:

```sh
git clone https://github.com/ShuklinAleksandr/mirea-v78-map.git
cd mirea-v78-map
npm ci
npm run dev
```

Откройте адрес из терминала, обычно `http://localhost:5173`. Для остановки используйте `Ctrl+C` или `npm run stop`. Для полного набора тестов также нужен Python 3, доступный как `python3`.

[Опубликованный сайт](https://shuklinaleksandr.github.io/mirea-v78-map/) открывается без компьютера автора. На iPhone можно добавить его на экран Домой через меню Safari. Это веб-версия, а не IPA/TestFlight; для первого открытия карты нужен интернет. Для геопозиции и датчиков нужны HTTPS, разрешение пользователя и поддержка устройства.

Для просмотра из той же локальной сети:

```sh
npm exec -- vite --host
```

Откройте на телефоне адрес `Network` из терминала. HTTP по локальному IP подходит для просмотра карты, но не для полноценной проверки датчиков.

## Публикация одной веб-сборки

Для корня сайта:

```sh
npm run build
npm run preview
```

Для GitHub Pages с путём `/mirea-v78-map/` на Mac/Linux:

```sh
BUILD_BASE=/mirea-v78-map/ npm run build
```

В PowerShell:

```powershell
$env:BUILD_BASE = "/mirea-v78-map/"
try {
  npm run build
} finally {
  Remove-Item Env:BUILD_BASE
}
```

Публикуется всё содержимое `dist/`, включая `assets/`, worker-файлы и `data/`. Открытие `index.html` через `file://` не заменяет веб-сервер. GitHub Pages использует ветку `gh-pages`; исходники находятся в `main`. Не добавляйте в публикацию архивы исходных материалов и локальные записи пользователей.

Перед нативной сборкой `BUILD_BASE` должен отсутствовать или быть равен `/`. Android собирается по [MOBILE.md](MOBILE.md). Для iOS на другом Mac передаётся весь репозиторий, затем выполняются установка зависимостей, синхронизация и сборка в Xcode. Simulator App нельзя установить на iPhone; для устройства нужны Team и подпись владельца.

## Что проверить перед выпуском

Проверьте поиск, избранное после переноса, маршрут между этажами, точку «От меня», кнопки этажей, 2D/3D, клавиатуру и поворот телефона. Отдельно проверьте щипок, перетаскивание с подписи, Android «Назад» и возврат из фона. Команда `npm run check` проверяет код и собирает веб; готовый APK/App требует отдельной компиляции и сравнения встроенных ресурсов.

Новые элементы управления не подтверждают геометрию или связность карты. Реальная точность GPS, проходимость маршрутов, компас и плавность на слабых телефонах проверяются отдельно; исторические отчёты не заменяют эти испытания.
