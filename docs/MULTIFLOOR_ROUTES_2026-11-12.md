# Маршруты через несколько этажей — проверка 12 ноября 2026

Ограничение «маршрут строится максимум через два этажа» не подтвердилось. Текущий движок строит реальные цепочки исходного графа через четыре физических этажа. Эта проверка отделена от прежних аудитов: она выполнена заново 12 ноября, без изменения графа, дверей и геометрии.

## Проверенные примеры

| Начало  | Назначение | Результат                                                                                             |
| ------- | ---------- | ----------------------------------------------------------------------------------------------------- |
| Г-103-1 | Г-424      | Полный путь: этажи 1 → 2 → 3 → 4, три лестничных перехода                                             |
| Г-103-1 | Г-416      | Полный путь: этажи 1 → 2 → 3 → 4                                                                      |
| Б-110   | Б-402      | Полный путь: этажи 1 → 2 → 3 → 4                                                                      |
| Г-103-1 | Г-424-3    | Путь через четыре этажа до общей Г-424; последний участок внутри помещения описан словами             |
| Г-424   | Г-424-3    | Точная внутренняя линия отсутствует и на том же этаже; доступна инструкция найти кабинет внутри Г-424 |

Для Г-103-1 → Г-424 отдельно проверены обратное направление и прохождение всех четырёх участков в синтетическом GPS-сценарии. У каждой лестницы ведение ждёт ручного подтверждения следующего этажа. Просмотр другого этажа сам по себе не продолжает маршрут. Этот сценарий проверяет программу, а не движение реального телефона по зданию.

## Почему некоторые маршруты не находятся

В `src/data/routing.js` Дейкстра обходит доступные рёбра до назначения либо до исчерпания очереди. Счётчика с ограничением числа этажей нет. Все вертикальные переходы разделяют путь на участки; интерфейс перечисляет все исходные этажи этих участков.

Разрывы относятся к другим причинам:

- Части исходного графа изолированы: между ними не сохранено соединение.
- Нельзя сокращать путь через посторонние подписанные кабинеты, туалеты и служебные комнаты. Такие области не считаются коридорами без подтверждения.
- Наличие помещения и даже флага `connected` не доказывает доступность его двери из общего коридора.

Для подтверждённой пользователем группы Г-424 действует `findNavigationRoute`: строится существующий путь до общей Г-424, затем показывается явный ручной этап. Точная функция `findRoute` не добавляет недостающие внутренние двери. Поэтому отсутствие точного пути до Г-424-3 не связано с количеством этажей.

Есть и неоднозначные одинаковые подписи. Например, у «В-402» три исходные записи: `v-78--floor-3--cti` и `v-78--floor-3--cuc` достижимы из Г-103-1, а `v-78--floor-3--ct9` изолирована. Автоматически объединять их или прокладывать между ними двери по одному названию нельзя; требуется сверка на месте.

## Перебор от одного старта

Числа этого раздела зафиксированы до добавления нового режима соседних индексных ориентиров. Его отдельный охват и полный список приведены в [отчёте о соседних кабинетах](NEARBY_INDEX_ROUTES_2026-11-12.md).

Начало: Г-103-1 (`v-78--floor-0--200`). Проверены все остальные **1147 записей `graph.rooms`**: кабинеты, туалеты, питание, медпункт, гардеробы и вход.

| Результат                     | Число назначений |
| ----------------------------- | ---------------: |
| Точный путь                   |              707 |
| Частичный путь до общей Г-424 |                5 |
| Путь отсутствует              |              435 |

Среди успешных результатов 667 содержат не менее трёх разных исходных планов, 233 — не менее четырёх. Максимум — пять исходных планов; **это не означает пять физических этажей**: в корпусах А и Г нумерация этажей относительно исходного плана различается.

Из 435 отказов 282 назначения находятся в другом компоненте сохранённого исходного графа. Для ещё 153 путь появляется только при снятии запрета проходить через посторонние подписанные помещения; такой путь не разрешался. Ограничения направленности, исключённые рёбра и подтверждённые перегородки при классификации сохранены.

Если считать только исходный тип `room`, проверены 1043 назначения: 663 точных пути, 5 частичных и 375 отказов. Это проверка **из одного начала**, а не всех пар и не процент подтверждённой доступности университета.

## Воспроизведение

```sh
node --test tests/multifloor-routing.test.mjs tests/routing.test.mjs tests/entrance-route.test.mjs tests/routing-isolated-endpoint.test.mjs
```

Новый отдельный тест использует настоящий граф В78 и проверяет:

1. Четыре физических этажа и три исходных лестничных ребра в обоих направлениях.
2. Ручное подтверждение каждого межэтажного перехода, без автоматической смены этажа по GPS.
3. Отсутствие выдуманной двери в Г-424-3 при сохранении частичного маршрута через все четыре этажа.

Граф проверки: `public/data/routing/v-78.json`; 16 237 узлов, 41 218 рёбер, 1148 записей `rooms`. SHA-256:

```text
a6f68d44482e87806a6a62d2c9717ce38ca7a2969e759320003898150c80958b
```

В отчёт и тесты не включены частные GPS-замеры. Успешный расчёт подтверждает непрерывность разрешённых исходных связей; текущие двери, ограничения доступа и фактическая проходимость требуют обследования в вузе.

Дополнительно в Chrome проверено построение Г-103-1 → Г-424 и ручное переключение всех четырёх этажей в desktop-окне 1365×900 и мобильном размере 390×844. Ошибок JavaScript и загрузки ресурсов не обнаружено; это проверка интерфейса, а не реальной прогулки.
