# Аудит навигации В-78 · 20 ноября 2026

Проверены локальные версии Android и веб на основе коммита `8a910d3`. В состав поставки входят пять планов Вернадского, 78. Исторические планы остальных кампусов использованы для дополнительных проверок исходного формата.

Последующий [аудит интерфейса](UI_AUDIT_2026-11-20.md) включает повторный перебор, проверку разных размеров экрана и сведения об актуальном APK.

## Что происходило при ходьбе

На пути Г-103-1 → Г-209 после перехода на второй этаж маркер терял линию даже при точных измерениях через три секунды. За это время пешеход проходил несколько коротких рёбер, а трекер искал продолжение слишком близко к предыдущему ребру. Исправлены выбор продолжения, удержание последней подтверждённой позиции при кратком скачке GPS и восстановление после временного сбоя геолокации. При движении через один перекрёсток дважды камера и подсказка используют расстояние, уже пройденное по маршруту.

В новом профиле кнопка «В путь» включает ведение по линии. Ранее сохранённый выбор пользователя учитывается. Настройка находится в разделе «Настройки → Ведение по линии маршрута». При устойчивом отклонении, потере сигнала или неопределённом этаже автоматическое продвижение приостанавливается. Этаж на лестнице подтверждает пользователь.

## Какие маршруты исправлены

- От главного входа к И-205-а через библиотеку построитель сократил число точек с 88 до 20, горизонтальную длину со 184,19 до 157,08 м и число инструкций с 14 до 11. Этой же линией пользуются ведение и карта. На выводимой прямой длиной 79,75 м по пути И-212-б → ИВЦ-133 все 53 моделированных измерения с боковым смещением до метра сопоставились с маршрутом.
- По пути А-209 → Г-213 исходный граф позволял пересечь лестничный проём около А-154. Исключены 46 горизонтальных рёбер, пересекающих этот проём. Подтверждённый лестничный переход и его подходы доступны.
- Две произвольные точки на одном разрешённом ребре теперь соединяются по соответствующему отрезку с учётом направления. Привязка временной точки учитывает закрытые рёбра.
- Сопоставление всех пар с независимым расчётом обнаружило 169 ошибочных отказов. Например, у Г-100.2 и Г-100а путь до соседнего помещения использует общую дверь. Граф знал обе стороны этой двери, но ответ терял ссылку на дверное ребро. Обе стороны теперь сохраняют эту ссылку и свои координаты. Все 169 запросов получили частичный маршрут с указанием действительной двери.
- Три видимые лестницы корпуса Д получили привязку к уже обследованным порталам. Проверяются координаты и области на обоих концах исходного ребра. Карточки объектов, у которых нет подтверждённого графового якоря, учитывают это при выборе действий.

## Проверка каждой пары

Охват включает 1 148 объектов каталога, дополнительные лестницы и объекты, которые открывались с плана. У объекта с несколькими названиями учитывался идентификатор, который получает построитель. Для 1 846 объектов вызван тот же `findIRouteOptions`, что работает в веб-воркере и в APK, с планами этажей. Обратное направление проверено отдельным вызовом. Ещё 1 846 запросов проверяют выбор одного и того же объекта на обоих концах. Произвольные пользовательские и GPS-координаты проверены отдельными сценариями.

В каждом успешном ответе проверяются начало и конец, направление и допустимость исходных рёбер, принадлежность промежуточных точек разрешённым помещениям, переходы между этажами, координаты инструкций и пересчёт длины по фактической линии. Выпрямленные отрезки дополнительно сверяются с поверхностью этажа. Для каждой предложенной альтернативы в корпус И проверяется выбранный проход. Для всех 1 316 756 пар каталога результат также сравнивается с независимой моделью связности и доступных соседних дверей.

Для 51 144 пар проверены оба варианта через библиотеку и по улице. Для 354 430 пар хотя бы один путь получил прямой участок. В итоговом прогоне все проверки геометрии и всех ответов прошли. Расхождений с независимой моделью для объектов каталога — 0.

От главного входа до 706 объектов построен точный маршрут, для 53 показан путь до известной двери. Ещё для 388 объектов существующий план и граф не подтверждают допустимый путь. Среди 759 доступных путей от главного входа 542 удалось выпрямить, суммарно убраны 11 249 промежуточных точек.

## Интерфейс, данные и сборки

- В Chromium проверены поиск по категориям и клавиатуре, карточки, избранное, ссылки и перезагрузка, этажи, маршрут от своего местоположения, смена варианта пути, жесты, 2D и 3D. Проверены настольный экран, портретная и альбомная ориентации телефона, корневой адрес и сборка с префиксом `/mirea-v78-map/`. В Firefox и WebKit отдельно проверены WebGL 2, пять планов, поиск, построение межэтажного маршрута и переход по шагам.
- Исправлены неполный список мест в поиске, выбор по Enter и скачок фокуса во время обновления GPS. При отказе в разрешении на геолокацию приложение сообщает результат запроса и предлагает ручную точку. Проверены отказ сети при запуске, повторная загрузка и работоспособность карты при недоступном дополнительном слое.
- В эмуляторе Android 16 проверены установка APK, запуск карты с выключенной сетью, переход по ссылке, получение моделированных координат через Android GNSS и Capacitor, следование маркера, возврат из фона, аппаратная кнопка «Назад» и поворот экрана. Инструментальный тест открывает каждый ресурс из описи установленного приложения.
- Проверены 23 исходных плана, 4 453 полигона, 40 742 стены и 2 600 дверей. В 26 видах восьми корпусов В-78 проверены подписанные помещения, отверстия и геометрия пола. Для 61 лестничной модели проверено размещение. Два расхождения с границами исходного плана уже отмечены в реестре. На трёх архивных кампусах отдельно проверены 4 800 запросов к исходному графу, включая 1 934 построенных пути.

Первый проход аудита включал **972 пройденных теста JavaScript**, пять пройденных JVM-тестов и один инструментальный тест Android. Сборки веба, debug APK, release APK и Android App Bundle завершились успешно. В установленном debug APK все 93 файла веб-сборки совпали по контрольным суммам. Проверена подпись APK по схеме v2. SHA-256 APK этого первого прохода — `be4b1b290c8ec549ced6120558e5a4690369f0e3fab3da30aa14aa517a450edd`.

После обновления транзитивных зависимостей `npm audit` сообщил о нуле известных уязвимостей. Android Lint оставил 30 предупреждений, в основном про значки и неиспользуемые ресурсы, при нуле ошибок. Vite предупредил о размере основного JS-файла и атрибутах импорта JSON с параметрами привязки GPS.

## Как повторить

```sh
npm ci
npm run check
npm audit
npm run data:check
node scripts/check-routing.mjs
node scripts/audit-route-reachability.mjs .native-build/audit/route-coverage
node scripts/audit-all-routes.mjs .native-build/audit/all-routes 10 .native-build/audit/route-coverage
npm run mobile:build:android
npm run mobile:check
node scripts/verify-native-artifacts.mjs
android/gradlew -p android :app:testDebugUnitTest :app:lintDebug
```

В каталоге полного перебора лежат `summary.json` с итогами, `endpoints.json` с объектами, `rows.json` с результатами по каждому началу и сжатая таблица `matrix.csv.gz`. В строках таблицы указано начало, в столбцах — назначение. Код 0 означает совпадающие точки, 1 — точный путь, 2 — частичный путь, 3 — отсутствие допустимого прохода, 4 — отсутствие привязки точки, 5 — ошибка проверки.

Физическая точность GPS и фактическая доступность дверей внутри университета требуют проверки на месте. Эмулятор и повторяемые траектории проверяют реакцию приложения на заданные измерения.
