# Участие в разработке

## Подготовка

Получите доступ к репозиторию и клонируйте его через Git или GitHub Desktop. Откройте папку, в которой лежит `package.json`, затем выполните:

```sh
npm ci
npm run dev
```

Нужен Node.js 24 (минимум 22.12); версия записана в `.nvmrc`. Для полного набора тестов нужен Python 3. Включены все необходимые для обычной сборки карты, фотографии и подготовленные данные; повторно извлекать XAPK не требуется.

## Ветка и Pull Request

Перед задачей обновите `main` и создайте отдельную ветку:

```sh
git switch main
git pull --ff-only
git switch -c feature/search-improvements
```

Замените имя ветки на название своей задачи. Если доступа на запись нет, используйте fork и отправьте Pull Request из него.

После изменений выполните:

```sh
npm run check
git diff
```

Для изменений нативного кода дополнительно соберите затронутую платформу и укажите устройство или симулятор. Веб-проверка в GitHub Actions не заменяет Android/Xcode-компиляцию.

```sh
git add .
git diff --cached
git commit -m "Improve nearby search"
git push -u origin feature/search-improvements
```

Откройте Pull Request в `main`. Кратко опишите проблему, получившееся поведение и фактически выполненные проверки. Для изменений интерфейса приложите снимки; для геометрии или маршрутов — источник и номера вопросов по карте. Шаблон Pull Request уже включён.

## Где менять код

| Область | Файлы |
| --- | --- |
| Интерфейс | `src/ui/`, `src/styles.css` |
| Сцена, камера, лестницы | `src/map/` |
| Поиск, маршруты, данные | `src/data/` |
| Системная геопозиция и компас | `src/location.js`, `src/heading.js` |
| Нативные плагины | `android/`, `ios/` |
| Исходные карты и фотографии | `public/data/`, `source/maps/` |
| Подготовка данных и сборка | `scripts/` |
| Проверки | `tests/` |

Подробности: [архитектура](docs/ARCHITECTURE.md), [формат данных](docs/DATA_FORMAT.md), [маршрутизация](docs/ROUTING.md), [мобильное окружение](docs/MOBILE.md).

## Задачи по карте

Используйте шаблон «Уточнение карты» в GitHub Issues. Укажите корпус, физический этаж, аудиторию или ориентир и отметьте место на плане/снимке. Если вопрос уже есть в [ВОПРОСЫ_ПО_КАРТЕ.md](ВОПРОСЫ_ПО_КАРТЕ.md), укажите его номер и сохраните ответ там же без перенумерации.

Геометрию и граф меняйте по проверенным планам, фотографиям или обследованию. Не соединяйте разрывы через стены и не добавляйте помещения или уровни по догадке. Принятый верхний марш главной лестницы сохраняется; открытые вопросы нижних спусков перечислены в [STAIRS_TODO_FOR_MAC.txt](STAIRS_TODO_FOR_MAC.txt).

Производственный интерфейс содержит только В78. Исходный архив остальных площадок нужен для воспроизводимости и тестов: его не следует удалять ради уменьшения репозитория или прохождения проверок.

## Мобильные сборки

Сначала подготовьте окружение по [docs/MOBILE.md](docs/MOBILE.md), затем запустите `npm run mobile:doctor`. Общая команда на Mac — `npm run mobile:build:macos`; она выполняет одну синхронизацию и обе компиляции. Для физического iPhone следуйте [XCODE_IPHONE.md](XCODE_IPHONE.md).

SDK, `node_modules`, кэши, файлы подписи и локальные сборки создаются на компьютере разработчика. APK и Simulator ZIP прикрепляются к Releases с датой, SHA-256 и ограничениями. Simulator App не является iPhone/TestFlight-сборкой.

## Документация и проверки

Изменив поведение, обновите соответствующий документ и добавьте осмысленную проверку, если она нужна. Не удаляйте тесты и исходные данные ради зелёного результата. Старые отчёты сохраняют исторический статус; результаты нового прохода записываются отдельно с датой.

[Документация](docs/README.md) содержит тематическую навигацию. Права на сторонние материалы описаны в [DATA_SOURCES.md](docs/DATA_SOURCES.md).
